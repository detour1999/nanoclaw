# Time Check

## What this is for

Time blindness: there is no "later," only now or not yet. The ADHD brain has a weak internal clock — duration isn't felt, time passing isn't noticed, and "I'll do it in a minute" can mean three hours. This skill anchors to actual time and surfaces what's realistic.

## How to run it

Run `date` first. Never estimate or ask the current time.

If the invocation names the next commitment, use it. Otherwise ask: "What's your next fixed commitment?" — or, if they don't have one, "What's the most time-sensitive thing today?"

If the commitment's time has already passed, say so first: "It's 4:11 — your 3pm was an hour ago." Then ask once: missed, or a different day? Don't calculate a window until that's answered.

---

## Estimation tax

Apply to any estimate the user gives for their own work:
- Task they do routinely: +50%
- New, or a type that historically runs long (refactors, writing, anything "quick"): ×2
- Plus 15 min to start and 10 to stop, per task

If you don't know whether it's routine, pick one and say which: "Treating the refactor as new — plan for 2h25."

---

## Hyperfocus

If they came up for air surprised by the time, name it once: "You were in hyperfocus — about [X] hours. That's done now." Then: "What's the priority for the rest of today?" No shame, no lecture.

---

## Output format

Now: <time from date>
Next commitment: <what and when>
Window: <minutes from now until they must stop for the commitment>
Estimates: <their number → adjusted number, per task>
Fits: <what fits — usually one task; say plainly if nothing does>

## What not to do

- No vague "you have some time." Minutes.
- Do not shame lost time.
- Do not plan the whole day — just this window.
