# Switch

## What this is for

Task switching fatigue: the cognitive cost of ending one thing and starting another. ADHD makes this cost higher — the brain doesn't release the previous context cleanly, so the new task starts with interference. This skill closes the loop on the old task and opens the next one deliberately.

## How to run it

If the invocation already names both tasks, don't ask again. Otherwise: "What are you switching from, and what are you switching to?"

If the next task has a time attached ("meeting at 4"), run `date` first. That decides full vs. compressed switch.

---

## Half 1: Close the current task

Only the user knows the state. Ask for it in one message, three short prompts:

1. Where did you leave it? (actual state, not where it should be)
2. What's the first thing you'll do when you come back?
3. One thing to remember?

Write the note from their answer — they talk, you format:
Left at: <current state>
Re-entry: <first action when returning>
Remember: <one thing>

Send the note as its own message so it's easy to find in the chat on return.

---

## Half 2: Open the next task

Fill this in yourself from what you know; ask only for what's missing:
Session goal: <what done looks like in the time available>
Need: <file, tab, person, tool to begin>
First action: <one physical step>

---

## Compressed switch (forced, or no time)

When the switch is forced, or the clock says there's under ~10 minutes (or they're already late):
- Ask for one line on where they left the old task. Make it optional — skip is fine.
- Give the one first action for the new task.
- Offer to run the full close when they're back.

A partial close is better than none. Don't run a full close under time pressure.

## What not to do

- Do not recap the history of either task.
- Do not plan the entire next task — just the entry point.
- Do not skip the close half unless compressed. The close is what stops the old task bleeding into the new one.
